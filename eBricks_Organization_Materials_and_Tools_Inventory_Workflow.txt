1. EXECUTIVE OVERVIEW & INVENTORY ARCHITECTURE
--------------------------------------------------------------------------------
The eBricks Materials and Tools Inventory Workflow governs the end-to-end lifecycle 
of physical construction assets, materials, equipment, and machinery across an enterprise. 
The system bridges Headquarters (HQ Central Warehouse) purchasing and storage with 
field construction sites and individual project execution stages.

Key Architectural Pillars:
  1. Multi-Tenant Organization Isolation:
     All inventory data strictly resides under:
     /organisation/{orgId}/data/{collectionName}

  2. eBricks Structural Hierarchy (Organization -> Sites -> Projects):
     - Organization Level (HQ): Central Catalog Master, HQ Warehouse Stock, Global Purchases, 
       Organization-wide Allocation & Audit Control.
     - Site Level (siteId): Physical work location holding active allocated inventory, 
       site tool cribs, and local consumption.
     - Project Level (projectId): Specific sub-entity under a site used for job costing, 
       budget tracking, and stage-wise material utilization.

  3. Dual Inventory Lifecycle Models:
     - Consumable Materials: Tracked by unit quantity (e.g., bags, tons, meters). Quantities 
       decrease as materials are consumed in daily site work or project stages.
     - Non-Consumable Tools & Machinery: Tracked by asset count, individual serial numbers/tags, 
       current location, operational condition, and custody transfers (returnable assets).

  4. Real-Time Transactional Integrity:
     Stock calculations utilize atomic updates (Firestore FieldValue.increment or transactions) 
     and status transition guards to prevent negative stock, ghost allocations, or lost items.

--------------------------------------------------------------------------------
2. ORGANIZATION -> SITES -> PROJECTS STRUCTURAL INTEGRATION
--------------------------------------------------------------------------------

To avoid duplicate collections and redundant data entry across Organization, Sites, 
and Projects, eBricks applies a unified single-source data model:

  +--------------------------------------------------------------------------+
  |                     ORGANIZATION HQ WAREHOUSE                            |
  | Collection: /organisation/{orgId}/data/materials                         |
  | Collection: /organisation/{orgId}/data/tools                             |
  | - Holds Master Item Specs, Default Prices, Global Stock Quantities       |
  +--------------------------------------------------------------------------+
                                     |
                                     | Stock Dispatch / Transfer Request
                                     v
  +--------------------------------------------------------------------------+
  |                          CONSTRUCTION SITE                               |
  | Sub-document/Field: siteMaterialsAvailability / toolsInventory           |
  | Filter Tags       : siteId == "ST001", siteName == "Metro Station"      |
  | - Holds Site Available Quantities, Received Quantities, Site Stock Crib  |
  +--------------------------------------------------------------------------+
                                     |
                                     | Allocation / Consumption Tagging
                                     v
  +--------------------------------------------------------------------------+
  |                          PROJECT STAGE WORK                              |
  | Tagged Fields     : projectId == "PR001", projectStage == "Foundation"   |
  | - Records exact material consumption and tool usage against project      |
  |   budgets & stage progress reports without duplicating stock entities    |
  +--------------------------------------------------------------------------+

Data Relationship Mapping Rules:
  - An Organization (`orgId`) owns all Master Materials and Master Tools records.
  - A Site (`siteId`) belongs to an Organization (`orgId`) and holds site-level stock balances.
  - A Project (`projectId`) belongs to a Site (`siteId`). Material consumption and tool deployment 
    logs explicitly include both `siteId` and `projectId` for precise financial reporting.

3. MATERIALS INVENTORY WORKFLOW & STOCK CALCULATION LOGIC
--------------------------------------------------------------------------------

A. Material Categories & Master Catalog Management:
   - Materials are classified into standardized construction categories:
     1. Civil & Structural (Cement, Rebar Steel, Ready-Mix Concrete, Bricks, Aggregates, Sand)
     2. Plumbing & Piping (PVC Pipes, CPVC Fittings, Valves, Water Tanks)
     3. Electrical & Wiring (Conduits, Copper Wires, Switches, Distribution Boards)
     4. Finishing & Joinery (Tiles, Paint, Primer, Plywood, Hardware, Glass)
     5. Safety & Miscellaneous (Safety Nets, Scaffolding Clips, Curing Compound)

B. Stock Breakdown & Calculation Formulas:

   1. Company Warehouse Stock (HQ Available Stock):
      `Company Available Stock` = Total Purchases Received at HQ 
                                - Total Dispatched Quantities to Sites 
                                + Total Unused Stock Returned to HQ 
                                - Total Damaged/Wasted Quantity at HQ

   2. Site Inventory Stock (Site Available Stock):
      `Site Available Stock` = Total Received Quantities from HQ or Inter-Site Transfers
                             - Total Consumed Quantities (via Daily Supervisor Work Logs)
                             - Total Quantities Transferred to Other Sites
                             - Total Quantities Returned to HQ
                             - Total Recorded Site Wastage/Damage

   3. Total Enterprise Stock (Global Stock):
      `Total Enterprise Stock` = Company Available Stock + Sum(All Active Site Available Stocks)

C. Real-Time Consumption Logic:
   - When a Site Supervisor submits a Daily Work Log (`siteSupervisorEntries`) indicating material 
     usage (e.g., 20 bags of Cement used for "Plastering" under `projectId`), the system:
       a) Decrements `availableQuantity` in site material stock by 20.
       b) Increments `consumedQuantity` in site material stock by 20.
       c) Appends a consumption log entry to `materialmovementhistory`.
       d) Updates the site's daily expense summary in `totalSiteExpensesPerDay`.

4. TOOLS & MACHINERY INVENTORY WORKFLOW & STATUS TRACKING
--------------------------------------------------------------------------------

A. Dual Tracking Model for Tools & Equipment:

   1. Bulk / Small Tools (Quantity-based Tracking):
      - Items like Hand Trowels, Hammers, Chisels, Safety Helmets, Measuring Tapes.
      - Tracked by total count: `totalQuantity`, `availableAtCompany`, `allocatedToSites`, `damagedCount`.

   2. Heavy / High-Value Equipment (Serialized Asset Tracking):
      - Items like Concrete Mixers, Earth Movers (JCB/Excavator), Diesel Generators, 
        Tower Cranes, Needle Vibrators, Demolition Hammers, Total Station Laser Scanners.
      - Tracked as discrete asset entities with unique `assetTagId` or `serialNumber`.

B. Tool Asset Lifecycle & State Machine Transitions:

   [State 1: AT_COMPANY_WAREHOUSE]
     - Asset is stored in HQ Warehouse, ready for allocation.
     - Condition: "OPERATIONAL" | "NEEDS_SERVICING"

   [State 2: PENDING_DISPATCH / IN_TRANSIT]
     - HQ Admin or Warehouse Manager approves requisition and dispatches asset.
     - Transit manifest generated with vehicle/driver details.

   [State 3: ACTIVE_ON_SITE]
     - Destination Site Supervisor confirms receipt.
     - Tagged with active `siteId`, `projectId`, and `assignedSupervisorId`.

   [State 4: RETURN_PENDING]
     - Site completes work package and initiates return request to HQ or transfer request to another site.

   [State 5: UNDER_MAINTENANCE / REPAIR]
     - Equipment suffers breakdown or requires routine servicing. Sent to vendor or central workshop.

   [State 6: DECOMMISSIONED / SCRAPPED]
     - Asset damaged beyond economical repair or sold off. Removed from active enterprise availability.

State Transition Diagram:
  (AT_COMPANY_WAREHOUSE) ---> [IN_TRANSIT] ---> (ACTIVE_ON_SITE)
            ^                                         |
            |------------ [IN_TRANSIT] <--------------| (RETURN / TRANSFER)
            |                                         |
            v                                         v
   (UNDER_MAINTENANCE) <------------------------ (DAMAGED / REPAIR)
            |
            v
   (DECOMMISSIONED)

5. SITE-WISE ALLOCATION, REQUISITION & TRANSFER FLOW
--------------------------------------------------------------------------------

The inventory transfer workflow governs movements between Company Warehouse and Sites, 
or directly between two Construction Sites (Inter-Site Transfer).

A. Supported Inventory Movement Types:
   1. `HQ_TO_SITE`       : Standard allocation from HQ Central Stock to Site.
   2. `SITE_TO_SITE`     : Inter-site balance transfer (e.g., Site A excess steel to Site B).
   3. `SITE_TO_HQ`       : Surplus material or tool return from Site back to HQ Central Warehouse.
   4. `SITE_TO_REPAIR`   : Machinery sent from Site directly to Repair/Service Center.

B. Step-by-Step 5-Stage Requisition & Transfer Flow:

   Stage 1: Requisition Creation (Site Supervisor)
     - Supervisor selects required materials/tools, specifies required quantity, required date, 
       and target `siteId` & `projectId`.
     - System checks local stock and creates requisition document in:
       `/organisation/{orgId}/data/siteMaterialsRequest` or `/organisation/{orgId}/data/siteToolsRequest`
     - Status: `pending_manager_review` (Step 1).

   Stage 2: Technical Verification (Manager)
     - Site/Project Manager reviews technical necessity and stage requirement.
     - Manager verifies work phase needs 50 bags of cement and approves request.
     - Status: `pending_org_approval` (Step 2).

   Stage 3: HQ Financial Authorization & Stock Reservation (Organization Admin / HQ)
     - Organization HQ Admin checks HQ Warehouse stock availability (`availableQuantity`).
     - If stock is sufficient, HQ authorizes requisition and reserves stock.
     - Assigns transport details (Driver Name, Vehicle Number, Gate Pass ID).
     - Status: `pending_manager_clearance` (Step 3).

   Stage 4: Warehouse Dispatch & Dispatch Clearance (Warehouse Manager / Manager)
     - Warehouse Manager physically loads materials/tools onto dispatch vehicle.
     - System deducts stock from Sender (`availableQuantity -= quantity`) and tags stock as `IN_TRANSIT`.
     - Transfer record written to `/organisation/{orgId}/data/materialTransfer` or `toolsMovement`.
     - Status: `approved` / `in_transit` (Step 4).

   Stage 5: Receiver Physical Acknowledgment & Automatic Stock Credit (Site Supervisor)
     - Goods arrive at target Construction Site.
     - Supervisor verifies physical items against transport gate pass, enters received quantity, 
       and logs any damaged/shortage count.
     - Supervisor signs digital receipt.
     - System automatically:
         a) Credits target site stock (`siteMaterials` / `toolsInventory` available quantity += receivedQty).
         b) If damage/shortage reported, creates discrepancy log.
         c) Marks transfer document status as `COMPLETED` / `received` (Step 5).

7. VALIDATION RULES, CONCURRENCY & INTEGRITY CHECKS
--------------------------------------------------------------------------------

A. Stock Availability Validation Rules:
   1. Sufficient HQ Stock Guard:
      - Before authorizing an HQ -> Site material dispatch, the system verifies:
        `HQ availableQuantity >= requestedQuantity`
      - If `availableQuantity < requestedQuantity`, dispatch is blocked with error:
        "Insufficient stock at HQ Central Warehouse. Available: X, Requested: Y."

   2. Sufficient Site Stock Guard for Inter-Site Transfers & Consumption:
      - Inter-site transfer from Site A to Site B requires:
        `Site A availableQuantity >= transferQuantity`
      - Daily consumption log requires:
        `Site availableQuantity >= consumedQuantity`

B. Concurrency & Transactional Safety Rules:
   - All stock increment/decrement operations MUST execute inside Firestore Transactions 
     (`FirebaseFirestore.instance.runTransaction(...)`) or atomic `FieldValue.increment(...)`.
   - Never compute stock in frontend code as `newStock = oldStock - quantity` and write back 
     with a simple `.update()`, as concurrent updates will cause race conditions and lost stock updates.

C. State Machine Enforcement Rules:
   - Disallow skipping lifecycle steps. A transfer cannot enter `COMPLETED` status unless 
     it has previously transitioned through `IN_TRANSIT` / `approved`.
   - A tool tagged as `active_on_site` at Site A cannot be assigned to Site B without 
     a completed transfer manifest or return record.

D. Discrepancy & Damaged Cargo Handling:
   - When Receiver Supervisor inputs `receivedQuantity < dispatchedQuantity` in Stage 5:
       a) Receiver stock is credited strictly with `receivedQuantity`.
       b) A `discrepancyLog` object is appended to the transfer document.
       c) An automatic high-priority notification is dispatched to HQ Warehouse Manager and Org Admin:
          "⚠️ Transfer Discrepancy Alert: Manifest #MTRF_... short by X units."

8. REAL-TIME STOCK UPDATES & FRONTEND IMPLEMENTATION WORKFLOW
--------------------------------------------------------------------------------

A. Frontend Reactive Architecture (eBricks Web Application):
   - eBricks web UI uses real-time Firestore reactive listeners (`onSnapshot` / `StreamBuilder` / RxJS).
   - Whenever stock changes due to dispatch, transfer receipt, or daily work log consumption, 
     the Inventory Dashboard tiles and Site Stock Tables instantly re-render without page refresh.

B. Key UI Screens & Component Mapping:

   1. Inventory Master Hub Page:
      - Component: `OrganizationInventoryHub.jsx` / `organization_inventory_screen.dart`
      - Tabs:
        * Tab 1: Material Catalog & Stock Ledger (HQ Stock vs Site Stock Matrix)
        * Tab 2: Tools & Machinery Registry (Serialized Equipment Status Grid)
        * Tab 3: Stock Transfer & Allocation Management (Create Request, Dispatch, Receive)
        * Tab 4: Inventory Movement Audit Log & History Ledger

   2. Stock Allocation Modal / Form:
      - Component: `CreateMaterialTransferModal.jsx`
      - Select Sender Location (HQ / Site A), Recipient Site, Material, and Quantity.
      - Displays live available stock badge of selected Sender location.

   3. Supervisor Receipt Confirmation Modal:
      - Component: `ReceiveInventoryModal.jsx`
      - Allows Supervisor to inspect physical items, input actual received count, note damage, 
        and submit digital signature/acknowledgment.
