1. EXECUTIVE SUMMARY & SUBSYSTEM OVERVIEW
================================================================================

The Layout and Drawings subsystem in the eBricks/CST platform is an enterprise-grade
document management solution engineered specifically for construction projects.
It enables project managers and engineers to upload, version, manage, and distribute
critical architectural layouts, structural designs, MEP (Mechanical, Electrical,
Plumbing) drawings, and site blueprints to field supervisors and mobile teams in
real-time.

Key Value Propositions:
- Single Source of Truth: Field personnel always have access to current, active drawings.
- Strict Subscription Limits: Tier-based quotas governing active document count,
  deletions, and re-uploads (preventing infrastructure abuse).
- Multi-Tenant Data Isolation: Every document and storage object is strictly scoped
  under `/organisation/{orgId}/`.
- Rich Mobile Viewing: Built-in high-resolution pan-and-zoom viewer for blueprints,
  in-app PDF webview, and seamless handoff for CAD (DWG/DXF) formats.

3. FRONTEND ARCHITECTURE & USER WORKFLOW
================================================================================

The frontend is implemented in Flutter (Dart) and structured into two primary screens:
1. Manager Screen: `lib/screens/manager/config_layout_and_drawing.dart`
2. Field Viewer Screen: `lib/screens/common/construction_documents.dart`
Supported by `lib/screens/common/web_view_screen.dart` for PDF rendering.

--------------------------------------------------------------------------------
3.1. MANAGER FLOW: UPLOAD & CONFIGURATION (TAB 0)
--------------------------------------------------------------------------------
File: `lib/screens/manager/config_layout_and_drawing.dart` (LayoutAndDrawingsPage)

Step 1: Initialization & Subscription Guard Check
- The page mounts with TabController (2 tabs: Upload & Configure, Drawings Directory).
- Calls `SubscriptionLimitService.getActivePlanLimits()`.
- Resolves `DrawingPlanLimits` (Free Trial, Silver, Gold, Platinum, Enterprise).
- Asynchronously queries `_fetchAllSitesData()` by fetching:
  * `FirestoreService.getCollection('Site')`
  * `FirestoreService.getCollection('siteSupervisorMap')`
  * `FirestoreService.getCollection('projects')`
- Merges site IDs into canonical site IDs using `ExpenseService.formatCanonicalSiteId()`.

Step 2: Site Selection & Metadata Auto-Fill
- User selects a Site from the dropdown.
- Callback `_onSiteSelected(siteId)` executes:
  * Clears any previous staged documents.
  * Auto-populates Supervisor Name, Project Name, and Project Stage.
  * Queries Firestore for site-level drawing metrics:
    `SubscriptionLimitService.getSiteDrawingUsage(siteId)`
  * Queries existing configurations:
    `FirestoreService.getCollection('siteDrawings').where('siteId', isEqualTo: siteId)`
  * Dynamically computes `_isUploadLockedForCurrentSite` based on active docs
    versus plan maximums.

Step 3: Staged Document Selection (Local File Picker)
- User enters:
  * Document Name (e.g., "Ground Floor Structural Layout")
  * Purpose / Description (e.g., "Foundation column layout & rebar details")
- User taps "Attach Blueprint File":
  * Pre-checks `_isUploadLockedForCurrentSite`. If locked, shows limit dialog.
  * Invokes `FilePicker.platform.pickFiles(type: FileType.custom, allowedExtensions: ['pdf', 'doc', 'docx', 'png', 'jpg', 'jpeg', 'dwg', 'dxf'])`.
  * Extracts file name, size (formatted in KB/MB), and extension.
  * Stores in memory as `PlatformFile`.

Step 4: Adding to In-Memory Staging Queue
- User taps "ADD TO STAGING LIST":
  * Validates inputs (Doc Name, Purpose, Attached File).
  * Enforces subscription check:
    `(currentActiveDocs + currentlyStaged + 1) <= maxActiveDocsPerSite`
  * Enforces re-upload rules (e.g., Silver does not allow re-upload; Gold allows max 1).
  * Creates a `DrawingDocItem` object and appends to `_stagedDocuments` list.
  * Form inputs are reset for the next entry.

Step 5: Cloud Upload & Database Commit
- User taps "SAVE & UPLOAD DRAWINGS":
  * Performs server-side pre-validation:
    `SubscriptionLimitService.canUploadDrawing(siteId, count, planName)`.
  * If validation fails, triggers `SubscriptionLimitService.showLimitReachedDialog()`.
  * If allowed, sets `_isSaving = true`.
  * Iterates through `_stagedDocuments`:
    - For each un-uploaded item, calls:
      `AppStorageService.uploadDrawingDoc(siteId, fileName, file, bytes)`.
    - Uploads file binary to Firebase Cloud Storage.
    - Captures `downloadUrl` and `storagePath`.
  * Prepares standardized Document ID:
    Format: `DRAWING_{cleanSiteId}_{yyyyMMdd}` (e.g., `DRAWING_SITE_001_20261006`).
  * Fetches any existing document with this ID to merge/deduplicate `siteDocs` array.
  * Commits payload to Firestore `siteDrawings` collection with `SetOptions(merge: true)`.
  * Records metrics in `siteDrawingsUsage`:
    `SubscriptionLimitService.recordDrawingUpload(siteId, count)`.
  * Displays success confirmation dialog, clears form, and switches to Directory Tab.

--------------------------------------------------------------------------------
3.2. MANAGER FLOW: DRAWINGS DIRECTORY & MANAGEMENT (TAB 1)
--------------------------------------------------------------------------------
File: `lib/screens/manager/config_layout_and_drawing.dart` (Directory Tab)

Features:
- Live Search Bar: Real-time filtering by Site ID, Project Name, Document Name,
  or Purpose description.
- Document Configuration Cards:
  * Displays Site ID, Project Name, Supervisor Name, Upload Date, and Total Document Count.
  * Action Button 1: "Load in Editor" (Loads saved config back into Tab 0).
  * Action Button 2: "Delete Set" (Triggers quota-validated set deletion).
- Expanded Sub-Documents List:
  * Lists each blueprint with file type badge (PDF, PNG, DWG, etc.), file size,
    purpose note, and upload timestamp.
  * View Button: Opens preview viewer modal.
  * Download Button: Initiates browser / OS download.
  * Delete Button: Deletes individual document from array after checking plan quota.

Deletions & Governance in Directory:
- Deleting Entire Set (`_deleteDrawingSet`):
  * Invokes `SubscriptionLimitService.canDeleteDrawing(siteId, planName)`.
  * Checks if plan permits deletions (Silver = No, Gold = 1 allowed, Platinum/Enterprise = Unlimited).
  * Shows tailored confirmation dialog alerting Gold users that this consumes their 1 deletion.
  * If confirmed:
    `FirestoreService.getCollection('siteDrawings').doc(docId).delete()`
    `SubscriptionLimitService.recordDrawingDelete(siteId, count)`
- Deleting Single Document (`_deleteIndividualDocument`):
  * Performs same quota validation.
  * Removes item from `siteDocs` array.
  * If `siteDocs` becomes empty, deletes parent Firestore document; otherwise updates array.
  * Records delete operation in `siteDrawingsUsage`.

--------------------------------------------------------------------------------
3.3. SUPERVISOR / ENGINEER FLOW: FIELD DOCUMENT VIEWER
--------------------------------------------------------------------------------
File: `lib/screens/common/construction_documents.dart` (ConstructionDocuments)

Step 1: Screen Entry & Site Selection
- Accessible directly from `SupervisorDashboard` via the "Construction Documents" menu tile.
- Loads assigned sites list.
- User selects a site.

Step 2: Drawing Retrieval (Query Hierarchy)
- `_fetchSiteData(siteIdentifier)` runs multi-step lookup to ensure robust matching:
  1. Searches `siteDrawings` by `siteId == cleanInput` or `siteId == canonicalId`.
  2. If not found, attempts direct document ID lookup:
     `DRAWING_{canonicalId}`, `DRAWING_{cleanInput}`, or `{cleanInput}`.
  3. If not found, scans recent drawings for substring match.
  4. If no drawings exist, falls back to `siteSupervisorMap` to display site metadata
     and inform the user: "No construction drawings uploaded for this site yet".

Step 3: Rendering & Inspection
- Displays Site Header (Site Name, Supervisor, Project Phase, Date).
- Renders Drawing Document Cards for every blueprint in `siteDocs`:
  * Title, Purpose, File Name, and Size.
  * "View Document" button.
  * "Download" button.

--------------------------------------------------------------------------------
3.4. IN-APP DOCUMENT VIEWERS & HANDLERS
--------------------------------------------------------------------------------

1. High-Resolution Blueprint Images (PNG, JPG, JPEG, WEBP, GIF, BMP):
   - Opens custom modal dialog with black backdrop.
   - Powered by Flutter's `InteractiveViewer`:
     * `minScale: 0.5`, `maxScale: 5.0`
     * Double finger pinch-to-zoom and drag-to-pan across large architectural drawings.
     * Loading progress indicator with cumulative bytes tracking.
     * Download button directly in header.

2. PDF Documents (Blueprints & Engineering Reports):
   - On Mobile: Launches `WebViewScreen(title, url)` (`lib/screens/common/web_view_screen.dart`).
     * Uses `webview_flutter`.
     * If URL points to raw PDF, wraps URL in Google Docs Viewer embed:
       `https://docs.google.com/gview?embedded=true&url={encodedUrl}`
     * Handles progress indicator and web error states.
   - On Web / Desktop: Uses `url_launcher` to open in native browser tab.

3. CAD & Vector Files (DWG, DXF, DOC, DOCX):
   - DWG / DXF cannot be rendered natively inside mobile webviews without heavy CAD engines.
   - The app uses `url_launcher` (`LaunchMode.externalApplication`) to hand off the file
     to AutoCAD Mobile, DWG FastView, or the device's native file viewer.

4. BACKEND ARCHITECTURE & DATA STORAGE
================================================================================

The backend relies on Google Cloud Firestore and Firebase Cloud Storage,
orchestrated via client-side Dart service abstractions that enforce multi-tenancy.

--------------------------------------------------------------------------------
4.1. MULTI-TENANT FIRESTORE PATH RESOLUTION
--------------------------------------------------------------------------------
In the eBricks SaaS architecture:
- Primary Tenant Path: `/organisation/{orgId}/{collectionName}/{docId}`
- Fallback Root Path:  `/{collectionName}/{docId}`
- Orchestrated dynamically via `FirestoreService.getCollection(collectionName)`.

--------------------------------------------------------------------------------
4.2. COLLECTION: siteDrawings (Master Document Ledger)
--------------------------------------------------------------------------------
Purpose:
  Stores the configuration, metadata, and cloud storage links for drawing sets
  associated with each site.

Document ID Schema:
  Standardized Deterministic ID: `DRAWING_{cleanSiteId}_{yyyyMMdd}`
  Example: `DRAWING_SITE_BLR_01_20261006`

Document Schema Definition:
{
  "docId": String,                  // e.g. "DRAWING_SITE_BLR_01_20261006"
  "siteId": String,                 // Canonical site ID (e.g. "SITE_BLR_01")
  "projectName": String,            // Name of project (e.g. "Prestige Tech Park")
  "supervisorName": String,         // Assigned supervisor (e.g. "Ramesh Kumar")
  "projectPhase": String,           // Project phase (e.g. "Foundation / Framing")
  "date": String,                   // Date string "dd/MM/yyyy"
  "formattedDate": String,          // Date string "dd-MM-yyyy"
  "createdAt": Timestamp,           // Server timestamp when created
  "updatedAt": Timestamp,           // Server timestamp when last updated
  "createdDateIso": String,         // ISO 8601 string
  "status": String,                 // "Active"
  "totalDocuments": Number,         // Count of active documents in siteDocs
  "siteDocs": [                     // Array of blueprint document objects
    {
      "docId": String,              // Unique item ID (e.g. "DOC_1728212400000")
      "docName": String,            // User title (e.g. "Ground Floor Column Layout")
      "purpose": String,            // Description (e.g. "Structural column placements")
      "fileName": String,           // Original file name (e.g. "column_layout_v2.pdf")
      "docUrl": String,             // Cloud download URL or file name
      "fileUrl": String,            // Firebase Cloud Storage public download URL
      "storagePath": String,        // Full storage bucket path
      "fileType": String,           // Extension: "pdf", "dwg", "png", "jpg"
      "fileSizeBytes": Number,      // Integer bytes (e.g. 4194304)
      "fileSize": String,           // Human-readable size (e.g. "4.0 MB")
      "uploadDate": String,         // Upload date "dd/MM/yyyy"
      "uploadedAt": String,         // ISO timestamp
      "isCloudUploaded": Boolean    // true
    }
  ]
}

--------------------------------------------------------------------------------
4.3. COLLECTION: siteDrawingsUsage (Site Usage & Quota Ledger)
--------------------------------------------------------------------------------
Purpose:
  Maintains an immutable historical record of uploads, re-uploads, and deletions
  for each site. This is critical for enforcing subscription plan restrictions
  (e.g., Gold plan 1 delete and 1 re-upload maximum).

Document ID:
  Cleaned Site ID: `{cleanSiteId}` (e.g. "SITE_BLR_01")

Document Schema Definition:
{
  "siteId": String,                 // Canonical site ID
  "totalUploadCount": Number,       // Cumulative total uploads performed
  "reuploadCount": Number,          // Cumulative re-uploads (totalUploadCount - 1)
  "deleteCount": Number,            // Cumulative document deletions performed
  "lastUploadedAt": Timestamp,      // Server timestamp of last upload
  "lastDeletedAt": Timestamp,       // Server timestamp of last deletion
  "updatedAt": Timestamp            // Server timestamp
}

--------------------------------------------------------------------------------
4.4. FIREBASE CLOUD STORAGE ARCHITECTURE & SCOPED FILE PATHS
--------------------------------------------------------------------------------
File binary data is uploaded to Firebase Cloud Storage via `AppStorageService`.

Storage Path Hierarchy:
  `organisation/{orgId}/drawings/{cleanSiteId}/{timestamp}_{cleanFileName}`

Example Storage Object:
  `organisation/ORG_ROOKS_01/drawings/SITE_BLR_01/1728212400000_column_layout_v2.pdf`

Storage Service Methods:
  - `AppStorageService.uploadDrawingDoc()`
  - Handles Web (Uint8List bytes) and Mobile/Desktop (File object path).
  - Automatically infers MIME content-type (e.g., `application/pdf`, `image/png`,
    `application/acad` for dwg).
  - Returns `StorageUploadResult` containing `downloadUrl`, `storagePath`, and `fileSizeBytes`.

--------------------------------------------------------------------------------
4.5. AUXILIARY / REFERENCE COLLECTIONS
--------------------------------------------------------------------------------
- `Site`: Master list of construction sites. Fields: `siteName`, `siteCode`, `location`.
- `siteSupervisorMap`: Mapping between site, supervisor email/name, and assigned project.
- `projects`: Master project records linking `siteId` and `projectName`.

--------------------------------------------------------------------------------
5.2. PRE-UPLOAD VALIDATION ENGINE (`canUploadDrawing`)
--------------------------------------------------------------------------------
Function: `SubscriptionLimitService.canUploadDrawing({siteId, newDocsCount, currentPlanName})`

Validation Rules:
1. Active Document Capacity Check:
   - Queries `siteDrawings` to count currently active documents.
   - If `activeDocsCount + newDocsCount > maxActiveDocsPerSite`:
     * Returns `isAllowed: false`.
     * Message: "You have reached your limit of X active document(s) for Site ...
       Upgrade to Platinum to upload up to 2 active documents per site."
2. Re-upload / Subsequent Upload Check:
   - Queries `siteDrawingsUsage` to check `totalUploadCount`.
   - If `totalUploadCount > 0` and `allowReupload == false` (Silver):
     * Returns `isAllowed: false`.
     * Message: "Re-uploading is not permitted on the Silver plan. Upgrade to Gold or Platinum."
   - If `reuploadCount >= maxReuploadsPerSite` (Gold limit 1/1):
     * Returns `isAllowed: false`.
     * Message: "You have exhausted your 1 allowed re-upload for Site ... on the Gold plan."
3. If all rules pass: Returns `SubscriptionValidationResult.allowed`.

--------------------------------------------------------------------------------
5.3. PRE-DELETE VALIDATION ENGINE (`canDeleteDrawing`)
--------------------------------------------------------------------------------
Function: `SubscriptionLimitService.canDeleteDrawing({siteId, currentPlanName})`

Validation Rules:
1. Deletion Permitted Check:
   - If `allowDelete == false` (Silver / Free Trial):
     * Returns `isAllowed: false`.
     * Message: "Document deletion is not permitted on the Silver plan. Users can upload and view documents only."
2. Delete Quota Exhaustion Check:
   - If `maxDeletesPerSite != null` and `deleteCount >= maxDeletesPerSite` (Gold limit 1/1):
     * Returns `isAllowed: false`.
     * Message: "You have exhausted your 1 allowed deletion for Site ... on the Gold plan."
3. If all rules pass: Returns `SubscriptionValidationResult.allowed`.

--------------------------------------------------------------------------------
5.4. USAGE ACCOUNTING & STATE TRANSITIONS
--------------------------------------------------------------------------------
- When Upload completes:
  `SubscriptionLimitService.recordDrawingUpload(siteId, count)`
  * Increments `totalUploadCount` by `count`.
  * If not first-time upload, increments `reuploadCount` by `count`.
  * Sets `lastUploadedAt = serverTimestamp()`.
- When Delete completes:
  `SubscriptionLimitService.recordDrawingDelete(siteId, count)`
  * Increments `deleteCount` by `count`.
  * Sets `lastDeletedAt = serverTimestamp()`.

7. ERROR HANDLING, INTEGRITY & RECOVERY PROCEDURES
================================================================================

1. Network Disruption during Storage Upload:
   - Staging items maintain `isCloudUploaded: false` until URL is received.
   - If an upload fails, error toast is presented and Firestore commit is aborted.
   - Prevents orphaned Firestore entries pointing to missing cloud files.

2. Document Overwrite & Merging:
   - The document ID is deterministic (`DRAWING_{cleanSiteId}_{yyyyMMdd}`).
   - When new documents are uploaded on the same day for the same site,
     the system fetches existing `siteDocs` and deduplicates by `docId` or
     `docName + fileName`, appending new items rather than overwriting existing records.

3. Corrupted / Missing Files Fallback:
   - If a cloud URL fails to render in the interactive image viewer, an error widget
     displays a broken image icon and an "Open External / Download" fallback button.

4. Multi-Tenant Cross-Contamination Prevention:
   - All collection queries route through `FirestoreService.getCollection()`.
   - All storage uploads prepend `organisation/{orgId}/`.
   - Tenants can never view or overwrite drawings belonging to another organization.
