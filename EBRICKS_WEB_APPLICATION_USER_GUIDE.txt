1. EXECUTIVE INTRODUCTION & SYSTEM ARCHITECTURE
================================================================================

1.1. About eBricks Platform
--------------------------------------------------------------------------------
eBricks (Construction Site Tracker - CST) is an enterprise-grade cloud construction 
management web and mobile platform designed to bridge the operational divide 
between Corporate Headquarters (Organization Executives) and Field Operations 
(Project Managers, Site Supervisors, Engineers, and Contractors).

eBricks delivers real-time visibility across:
  * Multi-site budgeting, financial tracking, client cash inflow, and expenses.
  * 5-Stage hierarchical approval workflows for expenses, indents, and milestones.
  * Materials inventory, stock levels, and transfer movements with gate passes.
  * Equipment, machinery, and tools tracking with serial-level asset custody.
  * Workforce muster rolls, wage scales, contractor bills, and attendance.
  * Architectural blueprints, MEP drawings, and CAD document distribution.
  * Cost-saving performance incentives for site supervisors upon stage completion.
  * Vehicle fleet management, daily trip logs, fuel consumption, and maintenance.

1.2. High-Level Technical Architecture
--------------------------------------------------------------------------------
The eBricks web client is built on modern web standards:
  * Frontend Framework: React 18+ with Vite tooling for lightning-fast HMR.
  * Routing: React Router DOM with role-based Route Guards.
  * Styling: Tailored responsive UI with TailwindCSS, Lucide iconography, and HSL 
    palettes (#0B3470 deep navy primary brand).
  * Backend & Database: Google Cloud Firestore with real-time websocket subscriptions.
  * Storage: Firebase Cloud Storage for blueprints, invoices, and vouchers.
  * Payment Engine: PayU India integration for automated subscription licensing.
  * Security: Multi-tenant tenant scoping, JWT session encryption, and role-based guards.

1.3. Multi-Tenant Organization Isolation
--------------------------------------------------------------------------------
eBricks strictly isolates data at the database layer. Every organization operates 
within its own partition under the Firestore document path:
    /organisation/{orgId}/

All project collections are nested within this tenant namespace:
  - /organisation/{orgId}/sites
  - /organisation/{orgId}/projects
  - /organisation/{orgId}/siteSupervisorEntries
  - /organisation/{orgId}/siteMaterialsRequest
  - /organisation/{orgId}/siteToolsRequest
  - /organisation/{orgId}/siteSupervisorProjectStageSchedule
  - /organisation/{orgId}/pettyCashAccounts
  - /organisation/{orgId}/pettyCashRequests
  - /organisation/{orgId}/pettyCashExpenses
  - /organisation/{orgId}/siteDrawings
  - /organisation/{orgId}/workers
  - /organisation/{orgId}/workerAttendance
  - /organisation/{orgId}/materials
  - /organisation/{orgId}/tools
  - /organisation/{orgId}/vehicles
  - /organisation/{orgId}/contractors

No organization can view, query, or mutate another organization's records.

1.4. Real-Time Synchronization Engine
--------------------------------------------------------------------------------
The web application uses Firestore `onSnapshot` real-time listeners across all 
active pages. When an on-site supervisor enters a daily expense or muster roll 
from the mobile app:
  1. The entry is committed to Firestore in milliseconds.
  2. The Manager Dashboard immediately reflects the pending approval badge.
  3. The Organization Finance Page automatically recalculates total expenditures.
  4. The global notification banner dispatches an alert across active browser tabs.

    - Daily attendance marking (worker muster rolls).

    - Construction drawings inspection (high-resolution pan, zoom, and CAD review).
    - Petty cash receipt submission and end-of-cycle balance reconciliations.

2.4. Contractors & Labour Workforce (Subcontractors & Daily Wagers)

  * Persona: Subcontractors (Masons, Carpenters, Electricians, Plumbers) & Labourers.
  * Responsibilities:
    - Execution of specialized work orders and physical construction tasks.
    - Daily wage muster roll recording (Full day, Half day, Overtime).

  * Access: Managed centrally within the Workforce and Contractors Hub.

3. AUTHENTICATION, SESSIONS & PASSWORD MANAGEMENT
================================================================================

3.1. Dual Login Interface (Organization vs Manager)
--------------------------------------------------------------------------------
The login portal (`/login`) features a segmented role selector:
  1. Organization Administrator Tab:
     - Log in using registered Organization Email or Enterprise Identifier.
     - Directs authorized users to `/organization/dashboard`.
  2. Operations Manager Tab:
     - Log in using Manager Email, Unique Username, Manager ID (e.g., MGR-104), 
       or registered Contact Number.
     - Directs authorized users to `/manager/dashboard`.

3.2. Identifier Resolution & Credential Validation
--------------------------------------------------------------------------------
When a user logs in, the `authService.js` engine executes an intelligent lookup:
  - For Organization Login:
    1. Validates email format and signs in via Firebase Authentication.
    2. Resolves Organization document in `/organisation/{orgId}`.
    3. Verifies subscription status (`isSubscriptionActive` and expiration date).
    4. Initializes organization workspace session.
  - For Manager Login:
    1. Inspects identifier: If formatted as an email, authenticates against Firebase.
    2. If identifier is a username or Manager ID, performs a fast lookup across 
       `/organisation/{orgId}/manager` collections.
    3. Resolves profile credentials, verifying account active status.
    4. Sets up encrypted manager session in browser localStorage.

3.3. 3-Step Secure OTP Password Reset Workflow
--------------------------------------------------------------------------------
If an Organization Admin or Manager forgets their password, they can trigger 
the automated 3-Step Password Reset Flow (`/forgot-password`):

  [Step 1: Email Identification]
    1. User clicks "Forgot Password?" on the login page.
    2. Enters registered account email address.
    3. Backend verifies email existence and checks a 60-second cooldown rate limit.
    4. Backend generates a cryptographically secure 6-digit OTP code and dispatches 
       a branded HTML email via SMTP.
    5. A session token is created with a 5-minute (300 seconds) expiry window.

  [Step 2: 6-Digit OTP Verification]
    1. UI displays 6 distinct OTP input blocks with auto-focus and paste support.
    2. Active countdown timers display:
       - OTP Expiry Timer (5:00 minutes).
       - Resend Code Cooldown Timer (60 seconds).
    3. User types the 6-digit code. The system verifies correctness without exposing 
       raw backend session states.
    4. Maximum 5 retry attempts are allowed before lockout.

  [Step 3: New Password Creation]
    1. Upon successful OTP verification, the user enters a new password.
    2. Password must satisfy security rules: minimum 6 characters, mixed case, numbers.
    3. Backend updates Firebase Authentication and Firestore tenant user records.
    4. Displays success confirmation banner and redirects to login with credentials prefilled.

3.4. Session Management & Auto-Refresh Mechanics
--------------------------------------------------------------------------------
  * Sessions are persisted in browser `localStorage` under `constructa_session`.
  * The `AuthContext.jsx` provider listens to Firebase Auth token state transitions.
  * Role Guards automatically intercept unauthorized route attempts:
    - If a Manager navigates to `/organization/*`, they are redirected to `/manager/dashboard`.
    - If an unauthenticated user enters any protected route, they are routed to `/login`.
  * Profile Menu provides a manual "Refresh Profile" action to pull updated 
    permissions without logging out.

4.2. Resource Limits & Quota Enforcement Engine
--------------------------------------------------------------------------------
Resource allocation is evaluated in real-time via `SubscriptionLimitService.js`:
  1. Pre-Site Creation Guard:
     - Evaluates `sites.length < maxProjects`.
     - If quota is reached, creation is blocked and `SubscriptionLimitModal` opens.
  2. Pre-Manager Onboarding Guard:
     - Evaluates `managers.length < maxManagers`.
     - Recommends plan upgrade if manager quota is exhausted.
  3. Pre-Supervisor Onboarding Guard:
     - Evaluates `supervisors.length < maxSupervisors`.

4.3. Drawing Upload & Replacement Governance
--------------------------------------------------------------------------------
Technical drawings and blueprints consume significant cloud storage and bandwidth.
eBricks enforces strict tier governance on layouts:
  * Free Trial & Silver:
    - Maximum 1 active document per site.
    - Deletion is disabled (0 deletes allowed).
    - Re-upload / replacement is disabled (0 re-uploads allowed).
    - If a user attempts to delete or replace, the system displays an upgrade prompt.
  * Gold Plan:
    - Maximum 1 active document per site.
    - Allows exactly 1 deletion and 1 replacement re-upload.
  * Platinum & Enterprise:
    - Up to 2 active documents per site concurrently.
    - Unlimited deletions and unlimited version replacements permitted.

4.4. Feature Gating & Upgrade Modals
--------------------------------------------------------------------------------
When an organization is on Free Trial:
  * Modules requiring Silver+ (Finance, Approvals, Petty Cash, Inventory Hub) render 
    a dedicated `PlanFeatureGate` interface explaining the requirement.
  * A prominent "Upgrade to Silver" or "Upgrade to Gold" button leads directly 
    to the subscription checkout.
  * Real-time limit modals display current count vs maximum allowable count.

4.5. PayU Payment Gateway Checkout & License Activation
--------------------------------------------------------------------------------
Organizations can upgrade subscriptions without waiting for manual invoices:
  1. Organization Admin navigates to `/organization/subscription`.
  2. Clicks "Upgrade Plan" or chooses Silver / Gold / Platinum.
  3. Selects duration: Monthly, 6 Months (Save 20%), or Yearly (Save 33%).
  4. For Platinum, adjusts interactive Site Slider (5 to 50+ sites) with dynamic pricing.
  5. Clicks "Proceed to Checkout". The system displays `PayUCheckoutModal`.
  6. Backend generates encrypted payment transaction hash and redirects to PayU gateway.
  7. Supports Credit/Debit Cards, Net Banking, UPI (GPay, PhonePe, Paytm), and Wallets.
  8. Upon payment confirmation, PayU redirects back with authorization token.
  9. The system immediately executes `activateSubscription()` in Firestore:
     - Updates `subscriptionPlan`, `maxProjects`, `maxUsers`, `subscriptionEndDate`.
     - Emits digital invoice and displays `TransactionCompletedScreen`.
     - Instantly unlocks all features without requiring re-login.

7. END-TO-END CORE WORKFLOWS (STEP-BY-STEP PROCESSES)
================================================================================

7.1. Workflow 1: New Project Inception, Setup, GPS Tagging & Staffing
--------------------------------------------------------------------------------
  1. Organization Admin or Manager opens `/manager/project-site-setup`.
  2. System automatically queries `SubscriptionLimitService` to verify site quota.
  3. [Step 1] User selects Project Category, Sub-Category, Stage, Contract Type, 
     and Project Status.
  4. [Step 2] User enters Client Full Name, Phone, Email, and Site Physical Address.
  5. User clicks "Auto-Detect GPS" -> Browser retrieves Latitude and Longitude.
  6. [Step 3] User enters Total Contract Budget, Client Advance Received, Start Date, 
     and Estimated End Date.
  7. User assigns primary Project Manager and Site Supervisor.
  8. Clicks "Create Project & Site". System executes atomic multi-document write:
     - Writes `/organisation/{orgId}/sites/{siteId}`.
     - Writes `/organisation/{orgId}/projects/{projectId}`.
     - Initializes initial financial balance ledger (`totalSiteExpensesPerDay`).
     - Initializes empty drawing usage quota document (`siteDrawingsUsage`).
  9. Project immediately appears across Organization and Manager dashboards.

7.2. Workflow 2: Universal 5-Stage Approval & Request Lifecycle
--------------------------------------------------------------------------------
Every expenditure, material purchase, and milestone passes through a 5-stage lifecycle:

  [Stage 1: Supervisor Submission]
    - Field Supervisor submits daily expense claim or material indent via mobile app.
    - Uploads physical bill photo and enters amount, category, and remarks.
    - Status set to: `pending_manager_review` (Step 1 of 5).
    - Notification dispatched to Operations Manager.

  [Stage 2: Manager Verification]
    - Manager opens `/manager/approvals`.
    - Inspects claim details and zooms in on bill photo attachment.
    - Manager clicks 'Verify': Sets status to `pending_org_approval` (Step 2 of 5).
    - (Or clicks 'Reject': Sets status to `rejected_by_manager` with mandatory reason).
    - Notification dispatched to Organization Admin.

  [Stage 3: Organization Tier-2 Authorization]
    - Organization Admin opens `/organization/approvals`.
    - Reviews verified claim and executive financial context.
    - Admin clicks 'Authorize': Sets status to `pending_manager_clearance` (Step 3 of 5).
    - (Or clicks 'Decline': Sets status to `rejected_by_org` with rejection notes).

  [Stage 4: Manager Clearance & Disbursal / Gate Pass]
    - For Payments: Manager/Finance transfers funds, inputs Bank UTR Reference Number, 
      and marks as 'Payment Disbursed' -> Status becomes `approved` (Step 4 of 5).
    - For Materials: Manager issues Dispatch Gate Pass with transporter details.

  [Stage 5: Site Receipt Confirmation]
    - Field Supervisor confirms physical arrival of cash or materials on site.
    - Clicks 'Confirm Receipt' -> Status transitions to `received` / `completed` (Step 5 of 5).
    - Immutable audit trail records timestamp, actor ID, and action at each step.

7.3. Workflow 3: Daily Field Progress, Consumption & Sundries Logging
--------------------------------------------------------------------------------
  1. Manager visits site and opens `/manager/daily-logs`.
  2. Selects Site ID and inspection date.
  3. Records weather condition and writes morning and afternoon progress summaries.
  4. In Materials Table: Clicks "Add Material", selects Cement (50 Bags @ Rs 380 = Rs 19,000).
  5. In Labour Table: Clicks "Add Trade", selects Masons (4 @ Rs 900 = Rs 3,600) and 
     Helpers (6 @ Rs 550 = Rs 3,300).
  6. Enters Sundries: Food (Rs 450), Transport (Rs 600), Fuel (Rs 1,200).
  7. System computes Total Daily Incurred Expense = Rs 28,150.
  8. Manager clicks "Save Daily Site Entry".
  9. Entry is stored under `/organisation/{orgId}/dailySiteLogs` and rolled into 
     site financial spent totals.

7.4. Workflow 4: Petty Cash Float Allocation, Disbursal & Reconciliation
--------------------------------------------------------------------------------
  1. Organization Admin sets up Site Imprest Float Account in `/organization/petty-cash` 
     (e.g., Float Limit: Rs 30,000, Low Balance Threshold: Rs 5,000).
  2. Supervisor submits Float Replenishment Request via mobile app.
  3. Manager verifies request in `/manager/petty-cash`.
  4. Organization Admin authorizes request and disburses Rs 25,000 via Net Banking 
     (enters UTR Reference: UTR98421045).
  5. Supervisor confirms receipt of cash on site. Available balance becomes Rs 25,000.
  6. Throughout the week, supervisor logs minor expenses (tea, nails, emergency courier) 
     with bill photos.
  7. Manager approves vouchers. Float balance automatically decrements.
  8. At month-end, supervisor submits End-of-Period Reconciliation Statement.
  9. Organization Admin reviews closing balance and settles via Carry Forward to 
     next cycle.

7.5. Workflow 5: Material Indent, Gate Pass Dispatch & Receipt Sign-Off
--------------------------------------------------------------------------------
  1. Supervisor identifies steel shortage on site and creates Material Requisition 
     (TMT 12mm Steel - 2 Metric Tons).
  2. Manager reviews indent in `/manager/approvals`, verifies against project stage, 
     and approves quantity.
  3. Organization Admin authorizes purchase order.
  4. Manager coordinates delivery from vendor, issues Dispatch Gate Pass 
     (GP-2026-0842), and assigns delivery truck.
  5. Delivery truck arrives at site. Supervisor inspects physical weight and tags.
  6. Supervisor clicks "Confirm Receipt" on mobile app.
  7. Site stock availability automatically increments by 2 Metric Tons in 
     `/manager/materials-stock`.

7.6. Workflow 6: Tools Checkout, Maintenance Tracking & Return Inspection
--------------------------------------------------------------------------------
  1. Supervisor submits Tool Requisition for a Concrete Vibrator Needle.
  2. Manager opens `/manager/approvals` -> Tools Stream.
  3. Manager selects available unit from warehouse: Asset ID `VIB-014` (Condition: Working).
  4. Manager dispatches tool with delivery notes.
  5. Supervisor confirms custody receipt on site. Asset location updates from 
     'HQ Warehouse' to 'Site Alpha'.
  6. When concreting finishes, supervisor initiates tool return.
  7. Manager inspects equipment at warehouse, confirms return, logs condition as 
     'Working', and updates asset status back to 'Available at HQ'.

7.7. Workflow 7: Workforce Onboarding, Daily Muster Roll & Wage Rollup
--------------------------------------------------------------------------------
  1. Manager configures trade wage scales in `/manager/labour-scales` (e.g., Barbender: 
     Rs 850/day, Overtime: Rs 150/hour).
  2. Manager registers workers in `/manager/workers` (Aadhaar, Phone, Skill, Daily Rate).
  3. Maps worker gang to construction site in `/manager/worker-mapping`.
  4. Each morning, supervisor/manager opens `/manager/attendance`.
  5. System loads mapped workers for the selected site and date.
  6. Marks attendance: Ramesh (Present), Suresh (Present + 2 hrs OT), Ganesh (Half Day).
  7. System computes daily wage obligation:
     - Full day = Base Rate.
     - Half day = Base Rate / 2.
     - Overtime = Base Rate + (OT Hours * OT Hourly Rate).
  8. Clicks "Save Muster Roll". Data rolls into monthly worker wage reports.

7.8. Workflow 8: Blueprints Upload, Quota Validation & Pan-Zoom Inspection
--------------------------------------------------------------------------------
  1. Project Manager opens `/manager/drawings`.
  2. Selects target site. System inspects subscription tier:
     - If Free Trial or Silver: Max 1 doc allowed. If 1 doc already exists, deletion 
       and re-upload buttons are locked with upgrade badges.
     - If Gold: 1 doc allowed; 1 deletion and 1 replacement allowed.
     - If Platinum: Up to 2 active docs allowed with unlimited replacements.
  3. Manager selects file (PDF or high-res blueprint image), inputs document title 
     (e.g., "Ground Floor Structural Layout Rev-2"), and clicks "Upload Blueprint".
  4. Document uploads securely to Firebase Cloud Storage. Metadata saved to Firestore.
  5. Field engineers open `/manager/construction-documents` or mobile app.
  6. Clicks "Inspect Blueprint" -> Opens `BlueprintViewerModal`.
  7. Field engineer can pinch, zoom in up to 500%, pan across structural grid lines, 
     rotate 90 degrees, or download offline.

7.9. Workflow 9: Milestone Labor Savings, Incentive Calculation & Rollup
--------------------------------------------------------------------------------
  1. A project stage (e.g., 'Foundation Stage') is completed on site.
  2. Organization Admin or Manager opens `/organization/incentives`.
  3. Selects Site ID -> System resolves assigned Supervisor -> Selects Stage.
  4. System queries:
     - Approved Planned Labor Budget for Foundation Stage: Rs 2,50,000.
     - Actual Labor Muster Cost Incurred during Foundation Stage: Rs 1,95,000.
  5. System calculates Cost Savings: Rs 2,50,000 - Rs 1,95,000 = Rs 55,000 saved.
  6. Because savings > 0, the interactive Incentive Percentage Slider unlocks.
  7. Management sets incentive slider to 20%.
  8. System calculates Supervisor Incentive Bonus: Rs 55,000 * 20% = Rs 11,000.
  9. Management clicks "Authorize & Save Incentive".
  10. System commits incentive expense document under `siteSupervisorIncentives`.
  11. The Rs 11,000 is automatically rolled into `totalSiteExpensesPerDay` and 
      reflected in site financial reports.

7.10. Workflow 10: Multi-Site Financial Auditing & Data Export
--------------------------------------------------------------------------------
  1. CFO or Auditor opens `/organization/reports`.
  2. Selects 'Financial Reports' -> 'Financial Statement'.
  3. Selects Date Range (e.g., Current Financial Quarter) and site scope.
  4. System aggregates:
     - Initial contract budgets.
     - Inflow payments received from clients.
     - Outflows: Material procurement, daily supervisor claims, contractor payouts, 
       manager expenses, petty cash spends, and incentives.
     - Net Operating Margin.
  5. Auditor clicks `ExportButton` -> System generates formatted Excel (.xlsx) and 
     CSV spreadsheets with customized headers and currency formatting.

7.11. Workflow 11: Plan Upgrade & PayU Payment Processing
--------------------------------------------------------------------------------
  1. Organization Admin hits site quota (e.g., 5 of 5 sites used on Silver plan).
  2. System displays `SubscriptionLimitModal` with "Upgrade to Gold" button.
  3. Admin navigates to `/organization/subscription`.
  4. Selects 'Gold Plan' (10 Sites, 5 Managers, 10 Supervisors) and 'Annual Billing' 
     (Rs 2,388/year).
  5. Clicks "Proceed to PayU Gateway".
  6. `PayUCheckoutModal` initializes encrypted checkout session.
  7. Admin completes payment via UPI or Corporate Net Banking.
  8. PayU confirms authorization. Backend updates organization subscription document.
  9. Web application immediately updates active site quota from 5 to 10.
  10. Admin can immediately create the 6th site without refreshing.

8. SYSTEM ALERTS, ERROR HANDLING & NOTIFICATIONS

8.1. Automated Financial Telemetry Alerts Engine (`projectAlerts.js`)
--------------------------------------------------------------------------------
eBricks continuously evaluates financial and timeline telemetry across all sites:
  1. Critical Expense Over Received Alert:
     - Condition: Total Expenses Incurred > Customer Payments Received.
     - Badge: "🚨 Expenses Exceed Received" (Red alert banner).
     - Rationale: Project is operating in a negative cash flow position funded by 
       company reserves rather than client milestones.
  2. Budget Overrun Warning Alert:
     - Condition: Total Expenses Incurred >= 90% of Total Contract Budget.
     - Badge: "⚠️ Budget Approaching Limit" (Amber alert).
     - If Expenses > 100%: "🚨 Budget Overrun Critical" (Red alert).
  3. Customer Payment Deficit Alert:
     - Condition: Total Contract Budget - Total Customer Payments Received > 50%.
     - Alerts management that substantial milestone receivables are overdue.

8.2. Overdue Milestones & Timeline Alerts
--------------------------------------------------------------------------------
  * Condition: Current Date > Estimated End Date AND Status != 'Completed'.
  * Badge: "⏰ Project Overdue" (Rose alert).
  * Prompts managers to negotiate contract time extensions or accelerate staffing.

9. FREQUENTLY ASKED QUESTIONS (FAQ) & BEST PRACTICES
================================================================================

9.1. General Operational FAQs
--------------------------------------------------------------------------------
Q: Can a Manager log in using their username instead of email?
A: Yes. The eBricks Manager login accepts Email, Unique Username, Manager ID (e.g., 
   MGR-102), or registered Contact Phone Number.

Q: How do I switch sites on the Organization Dashboard?
A: Click the "Project Selector" dropdown in the top header. Selecting a site filters 
   all metrics, expense rollups, and progress bars to that specific project. Select 
   "All Projects" to view portfolio aggregates.

Q: Can multiple supervisors be assigned to a single construction site?
A: Yes. eBricks supports primary and secondary supervisor assignments via the 
   Site-Supervisor Map (`/manager/supervisor-map`).

9.2. Financial & Petty Cash FAQs
--------------------------------------------------------------------------------
Q: Why does a site show a red alert saying "Expenses Exceed Received"?
A: This alert triggers when cumulative verified site expenses exceed total cash 
   received from the client, warning management of negative project cash flow.

Q: What happens if a petty cash float falls below the threshold?
A: The system automatically highlights the account in amber and allows managers 
   to trigger an automated Imprest Replenishment Request.

Q: Who can authorize stage incentive bonuses?
A: While Managers can verify and calculate incentives, final authorization and ledger 
   commitment requires Organization Administrator sign-off.

9.3. Supply Chain & Asset FAQs
--------------------------------------------------------------------------------
Q: Can I delete an architectural blueprint on the Silver Plan?
A: No. Free Trial and Silver plans permit 1 active blueprint per site in view-only 
   mode. Deletion and re-upload require upgrading to Gold (1 delete/replace) or 
   Platinum (unlimited).

Q: How do material reorder levels work?
A: In the Materials Catalog, each item has a `minReorderLevel` (e.g., 20 bags). When 
   on-hand site stock drops to or below this level, the dashboard displays a low-stock alert.

9.4. Administrator Best Practices Checklist
--------------------------------------------------------------------------------
  [x] Complete Master Configurations (Categories, Sub-Categories, Stages) before 
      creating your first live construction site.
  [x] Always auto-detect GPS coordinates during site setup to enable field geo-tagging.
  [x] Require all supervisors to upload clear physical bill photos for all expense claims.
  [x] Conduct weekly petty cash reconciliations to prevent cash leakage.
  [x] Set conservative material reorder thresholds to prevent construction stoppages.
  [x] Verify stage milestones and calculate supervisor incentives promptly upon stage 
      completion to motivate field personnel.
  [x] Export quarterly financial ledgers to Excel for corporate audit compliance.
