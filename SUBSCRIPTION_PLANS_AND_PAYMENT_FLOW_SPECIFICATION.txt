1. ARCHITECTURE OVERVIEW & MULTI-TENANT FIRESTORE PATHS
----------------------------------------------------------------------------------------------------
All subscription data, plan limits, payment receipts, and branding configs are stored inside 
the multi-tenant organization document namespace:

Root Document:
  /organisation/{orgId}

Nested Documents:
  1. Subscription Configuration: /organisation/{orgId}/data/subscription
  2. Branding Configuration    : /organisation/{orgId}/data/branding
  3. Admin & Credentials       : /organisation/{orgId}/data/admin  (and mirrored to data/data, admin/data)
  4. Referral Code             : /organisation/{orgId}/data/referralCode
  5. Organization Users        : /organisation/{orgId}/organizationUser/{userId}

Where:
- {orgId} is the dynamic tenant identifier (e.g., "cst_ABCConstructions_18-09-2026").
- Access control is validated on app boot and before any restricted action via SubscriptionLimitService.

B. PRICING & BILLING CYCLES
----------------------------------------------------------------------------------------------------
1. FREE TRIAL:
   - Duration: 14 Days
   - Amount: ₹0 (No payment required)

2. SILVER PLAN:
   - Monthly  (30 Days)  : ₹1 / month (or standard base price)
   - 6 Months (180 Days) : ₹594 (₹99/mo equivalent)
   - Yearly   (365 Days) : ₹1,188 (₹99/mo equivalent)

3. GOLD PLAN:
   - Monthly  (30 Days)  : ₹199 / month
   - 6 Months (180 Days) : ₹1,194 (₹199/mo equivalent)
   - Yearly   (365 Days) : ₹2,388 (₹199/mo equivalent)

4. PLATINUM PLAN (Dynamic Project Slider):
   - Formula based on selected project capacity (N = 5 to 50+ sites):
   - Monthly  (30 Days)  : ₹ (N * 39.90) / month
   - 6 Months (180 Days) : ₹ (N * 239.40)
   - Yearly   (365 Days) : ₹ (N * 478.80)
   - Presets Available in UI: 5, 10, 15, 20, 25, 30, 40, 50 Sites.

5. ENTERPRISE PLAN:
   - Custom Dedicated Deployment & SLA: Direct contact via sales / support modal.

----------------------------------------------------------------------------------------------------
C. LAYOUT & DRAWINGS ACCESS CONTROL POLICY
----------------------------------------------------------------------------------------------------
- Free Trial & Silver:
  * Maximum 1 active drawing file per site.
  * Delete is BLOCKED (allowDelete = false).
  * Re-upload is BLOCKED (allowReupload = false).
  * Prompt: "Upgrade to Gold or Platinum to delete and replace site drawings."

- Gold Plan:
  * Maximum 1 active drawing file per site.
  * Allow 1 Delete per site (maxDeletesPerSite = 1).
  * Allow 1 Re-upload per site (maxReuploadsPerSite = 1).

- Platinum & Enterprise:
  * Maximum 2 active drawing files per site concurrently.
  * Multi-delete allowed (unlimited delete & replace).
  * Multi-reupload allowed (unlimited).

----------------------------------------------------------------------------------------------------
B. CRYPTOGRAPHIC SIGNATURE GENERATION (SHA-512)
----------------------------------------------------------------------------------------------------
1. Request Hash Formula:
   hash = sha512(key|txnid|amount|productinfo|firstname|email|udf1|udf2|udf3|udf4|udf5||||||salt)

   Where:
   - key         : Active PayU Merchant Key
   - txnid       : Unique generated transaction ID (e.g. TXN_1726660000000_1234)
   - amount      : Formatted to 2 decimal places (e.g. "199.00")
   - productinfo : Sanitized product string (e.g. "ABC Constructions Gold Plan (Monthly)")
   - firstname   : Customer / Organization name (sanitized alpha-numeric)
   - email       : Customer email (valid email format)
   - udf1        : Organization Name / Identifier
   - udf2        : Plan Name
   - udf3        : Billing Cycle
   - udf4        : 'ebricks'
   - udf5        : 'ebricks_subscription'
   - salt        : Active PayU Merchant Salt

2. Response Hash Verification Formula:
   calculatedHash = sha512(salt|status||||||udf5|udf4|udf3|udf2|udf1|email|firstname|productinfo|amount|txnid|key)

   Verification Step:
   The client and backend compute the reverse SHA-512 hash and verify it matches the returned 
   'hash' parameter in the PayU response callback before granting access.

5. COMPLETE WORKFLOWS
====================================================================================================

----------------------------------------------------------------------------------------------------
WORKFLOW 1: NEW ORGANIZATION REGISTRATION & ONBOARDING
----------------------------------------------------------------------------------------------------
Step 1: Details Screen
  - Admin inputs: Org Name, Email, Phone, Username, Password.
  - Organization existence and duplicate usernames/emails are pre-validated.

Step 2: Branding Screen
  - Admin inputs: App Display Name, selects Theme Primary Color.

Step 3: Pricing & Plan Selection (PricingScreen)
  - Admin views plan comparisons and selects desired tier (Free Trial, Silver, Gold, Platinum).
  - Admin chooses billing cycle (Monthly, 6 Months, Yearly) or adjusts Platinum Project Slider.

Step 4: Payment Checkout (for Paid Plans)
  - If Free Trial: Payment is skipped (Amount = ₹0).
  - If Paid Plan: PayUCheckoutScreen is launched in a secure in-app WebView.
  - Post request is auto-submitted to PayU payment gateway with computed SHA-512 hash.
  - Customer completes payment via UPI / Card / NetBanking.
  - PayU intercepts callback (surl/furl) with payment status, txnid, payuMoneyId, and response hash.

Step 5: Firestore Provisioning & Account Activation
  - Multi-tenant path initialized: /organisation/{orgId}
  - Subscription doc created at: /organisation/{orgId}/data/subscription
  - Admin credentials stored at: /organisation/{orgId}/data/admin
  - Branding doc stored at     : /organisation/{orgId}/data/branding
  - Referral code generated at : /organisation/{orgId}/data/referralCode
  - Organization user added to : /organisation/{orgId}/organizationUser/{username}
  - Status flags updated: registrationStatus = 'COMPLETED', onboardingStep = 'COMPLETED'.

Step 6: Invoicing & Receipt Dispatch
  - Backend Cloud Function (or PayUService fallback) sends Tax Invoice to user's registered email.
  - Transaction Completed Receipt Screen is displayed (TransactionCompletedScreen) with full summary.
  - Navigates directly into OrganizationDashboard.

----------------------------------------------------------------------------------------------------
WORKFLOW 2: EXISTING SUBSCRIPTION UPGRADE / RENEWAL
----------------------------------------------------------------------------------------------------
Step 1: Admin navigates to Menu -> Manage Subscription -> [Upgrade / Change Plan].
Step 2: PricingScreen opens in "isManagingExisting = true" mode (Free Trial is hidden).
Step 3: Admin selects new Plan (e.g. Upgrading from Silver to Gold or Platinum).
Step 4: Upgrade Timing Options:
  - Immediate Upgrade:
    * Replaces active plan immediately.
    * Sets new subscriptionStartDate = now, subscriptionEndDate = now + durationDays.
    * Resets previous quotas and activates higher limits immediately.
  - Queued Upgrade:
    * If active plan has remaining days and user opts to queue:
    * Sets isUpgradeQueued = true, queuedPlan = _selectedPlan, queuedStartDate = currentEndDate.
    * Queued plan automatically promotes to active when current expiry date arrives.

Step 5: PayU Checkout completes payment.
Step 6: Merges updated subscription data in /organisation/{orgId}/data/subscription.
Step 7: Dispatches upgrade confirmation & Tax Invoice to registered email.

----------------------------------------------------------------------------------------------------
WORKFLOW 3: REAL-TIME ACCESS CONTROL & LIMIT ENFORCEMENT
----------------------------------------------------------------------------------------------------
1. Site Creation Check (SubscriptionLimitService.canCreateSite()):
   - Trigger: User taps "+ New Site" on Site Entry or Dashboard.
   - Logic:
     * Reads current project count vs limits.maxProjects.
     * If projectCount >= maxProjects: Blocks creation, displays Upgrade Modal prompting upgrade.
     * If projectCount < maxProjects: Allows creation.

2. User & Supervisor Creation Check (SubscriptionLimitService.canAddSupervisor()):
   - Trigger: User attempts to create a new Supervisor or Manager account.
   - Logic:
     * Compares active staff count against maxSupervisors / maxManagers / maxTotalUsers.
     * If limit reached: Blocks operation with warning: "Team member limit reached for {planName}".

3. Drawing Upload & Delete Check (SubscriptionLimitService.canUploadDrawing()):
   - Trigger: User uploads a layout or architectural drawing on a Site.
   - Logic:
     * Evaluates site's active drawings count vs DrawingPlanLimits.maxActiveDocsPerSite.
     * Evaluates whether deletion or re-upload is permitted under current tier.
     * If unauthorized: Blocks upload with detailed reason (e.g., "Silver plan allows 1 drawing per site with no deletion.").
