================================================================================
                    eBricks - FORGOT PASSWORD & RESET FLOW
================================================================================

1. OVERVIEW & ARCHITECTURE
--------------------------------------------------------------------------------
The Forgot Password flow in the eBricks mobile application is a secure, 3-step
OTP-verified mechanism designed to prevent unauthorized account access, credential
stuffing, and replay attacks.

Key Components:
  * Client (Flutter Mobile App):
      - Screen: lib/screens/common/reset_password_screen.dart
      - Auth Service: lib/services/auth_service.dart
  * Backend (Firebase Cloud Functions - Node.js):
      - functions/index.js (Endpoints: requestPasswordResetOtp, verifyPasswordResetOtp, completePasswordReset)
      - functions/emailService.js (Nodemailer SMTP email delivery with HTML template)
  * Database:
      - Cloud Firestore: `_password_reset_sessions` collection for tracking session states
      - Firebase Authentication: Updating primary user credentials
      - Firestore User Collections: Updating password records across organisations


================================================================================
2. STEP-BY-STEP USER JOURNEY & FLOW
================================================================================

[ Step 1: Request Password Reset (Email Entry) ]
-------------------------------------------------
  1. User opens the login screen and taps "Forgot Password?".
  2. Mobile App displays Step 1 (ResetPasswordStep.email).
  3. User enters their registered email address and taps "Send Verification Code".
  4. Client validates email format via regex.
  5. Client calls Cloud Function: `requestPasswordResetOtp`.
  6. Backend checks if the email exists in:
     - Firebase Authentication, OR
     - Firestore Organisation Users / SuperAdmin collections.
  7. If email is not registered:
     - Returns error: "This email ID is not registered with eBricks."
  8. If registered:
     - Checks rate limiting and resend cooldown (60 seconds).
     - Generates a cryptographically secure 6-digit numeric OTP (e.g., 049281).
     - Creates or updates session document in `_password_reset_sessions/{emailHash}`.
     - Dispatches branded HTML email via SMTP (Nodemailer) with the OTP code.
     - Returns success response containing:
         * sessionId
         * maskedEmail (e.g., ro***@gmail.com)
         * expiresInSeconds (300 seconds / 5 minutes)
         * resendCooldownSeconds (60 seconds)
         * resendCount & maxResends (5)
  9. Mobile App transitions to Step 2 (ResetPasswordStep.otp).


[ Step 2: OTP Verification (6-Digit Code) ]
--------------------------------------------
  1. Screen displays 6 distinct OTP input boxes with auto-focus and clipboard paste.
  2. UI displays active timers:
     - OTP Expiry Countdown (5:00 minutes).
     - Resend Cooldown Countdown (60 seconds).
  3. User types the 6-digit OTP received in their email.
  4. When all 6 digits are entered, verification triggers automatically.
  5. Client calls Cloud Function: `verifyPasswordResetOtp`.
  6. Backend performs strict security checks:
     - Verifies session exists and matches sessionId.
     - Checks if session has expired (> 5 minutes).
     - Checks if already used or locked.
     - Checks incorrect attempt count (Max: 5 attempts).
  7. If OTP is incorrect:
     - Increments incorrect attempt counter.
     - If attempts reach 5: Invalids OTP, permanently locks session, and returns:
       "Too many incorrect attempts (5). Current OTP has been invalidated."
     - If attempts < 5: Returns remaining attempts (e.g. "Incorrect OTP. 3 attempts remaining.")
  8. If OTP is correct:
     - Immediately invalidates OTP (sets `otp = null`) to enforce single-use consumption.
     - Generates a high-entropy, cryptographically secure `resetToken` (10-minute validity).
     - Marks session as `isVerified: true`.
     - Returns `resetToken` and `sessionId` to the client.
  9. Mobile App transitions to Step 3 (ResetPasswordStep.newPassword).


[ Step 3: Set New Password ]
-----------------------------
  1. Mobile App displays New Password and Confirm Password input fields.
  2. User inputs a new password. Real-time strength meter evaluates:
     - Length >= 6 characters
     - Length >= 8 characters
     - Combination of letters and numbers
     - Special characters (!@#$%^&*)
  3. Client checks that `newPassword == confirmPassword`.
  4. User taps "Reset Password".
  5. Client calls Cloud Function: `completePasswordReset`.
  6. Backend verifies:
     - `resetToken` matches the token in `_password_reset_sessions`.
     - Session is verified (`isVerified == true`) and not yet used (`isUsed == false`).
     - Token has not expired (within 10 minutes of OTP verification).
     - New password is valid (>= 6 characters).
  7. Backend applies changes:
     - Updates password in Firebase Authentication (`admin.auth().updateUser`).
     - Scans and updates password in associated Firestore user documents.
     - Marks session as `isUsed: true` and removes `resetToken` permanently (anti-replay).
  8. Backend returns success message.
  9. Mobile App transitions to Step 4 (ResetPasswordStep.success).
 10. User sees confirmation screen and taps "Back to Login" to sign in with their new password.


================================================================================
3. SECURITY RULES & SAFEGUARDS
================================================================================

1. OTP Format & Generation:
   - 6-digit numeric string formatted with leading zeros preserved (000000 - 999999).
   - Generated using Node.js `crypto.randomInt()`.

2. Expiration Rules:
   - OTP Validity: Exactly 5 minutes (300 seconds) from generation.
   - Reset Token Validity: Exactly 10 minutes (600 seconds) after OTP verification.

3. Resend & Rate Limiting:
   - Cooldown Period: 60 seconds required between consecutive OTP requests.
   - Maximum Resends: Up to 5 resend requests per session.
   - Idempotency & Debouncing: Prevents rapid duplicate requests within 15 seconds.

4. Brute-Force & Attempt Protection:
   - Maximum Incorrect Attempts: 5.
   - On the 5th failed attempt, the OTP is purged (`otp = null`), forcing user to restart.

5. Single-Use & Anti-Replay:
   - OTP is destroyed immediately upon successful verification.
   - `resetToken` is single-use and permanently revoked after password update.
   - Session marked `isUsed: true` with timestamp.

6. Privacy & Masking:
   - Email is masked in UI and Cloud Function logs (e.g., `ro***@gmail.com`).
   - Session records in Firestore store no plain passwords.


================================================================================
4. BACKEND API SPECIFICATIONS (CLOUD FUNCTIONS)
================================================================================

--------------------------------------------------------------------------------
A. requestPasswordResetOtp
--------------------------------------------------------------------------------
Description: Initiates password reset by validating email, creating session, and sending OTP email.
Type: HTTPS Callable / POST
Endpoint: /requestPasswordResetOtp

Request Payload:
{
  "data": {
    "email": "user@example.com",
    "isResend": false,
    "requestId": "1727932800000_emailHash"
  }
}

Success Response:
{
  "result": {
    "success": true,
    "message": "OTP sent successfully to your registered email address.",
    "sessionId": "SES_1727932800000_a1b2c3d4",
    "maskedEmail": "us***@example.com",
    "expiresInSeconds": 300,
    "resendCooldownSeconds": 60,
    "resendCount": 0,
    "maxResends": 5
  }
}

Error Response:
{
  "result": {
    "success": false,
    "error": "This email ID is not registered with eBricks. Please enter a valid registered email."
  }
}


--------------------------------------------------------------------------------
B. verifyPasswordResetOtp
--------------------------------------------------------------------------------
Description: Verifies the 6-digit OTP code against the active session.
Type: HTTPS Callable / POST
Endpoint: /verifyPasswordResetOtp

Request Payload:
{
  "data": {
    "email": "user@example.com",
    "otp": "123456",
    "sessionId": "SES_1727932800000_a1b2c3d4"
  }
}

Success Response:
{
  "result": {
    "success": true,
    "message": "OTP verified successfully.",
    "resetToken": "RST_1727932830000_9f8e7d6c5b4a3...",
    "sessionId": "SES_1727932800000_a1b2c3d4"
  }
}

Error Response:
{
  "result": {
    "success": false,
    "remainingAttempts": 3,
    "error": "Incorrect OTP. 3 attempts remaining."
  }
}


--------------------------------------------------------------------------------
C. completePasswordReset
--------------------------------------------------------------------------------
Description: Consumes the resetToken and updates the account password.
Type: HTTPS Callable / POST
Endpoint: /completePasswordReset

Request Payload:
{
  "data": {
    "email": "user@example.com",
    "resetToken": "RST_1727932830000_9f8e7d6c5b4a3...",
    "sessionId": "SES_1727932800000_a1b2c3d4",
    "newPassword": "NewSecurePassword123!"
  }
}

Success Response:
{
  "result": {
    "success": true,
    "message": "Password has been successfully updated. You can now log in with your new password.",
    "authUpdated": true,
    "firestoreUpdated": true,
    "updatedDocs": 1
  }
}

Error Response:
{
  "result": {
    "success": false,
    "error": "Unauthorized password reset attempt. Please complete OTP verification."
  }
}

5. FIRESTORE SESSION SCHEMA: `_password_reset_sessions/{emailHash}`
================================================================================

Field                     Type        Description
--------------------------------------------------------------------------------
email                     string      Registered email address (lowercased)
sessionId                 string      Unique session identifier (SES_timestamp_hex)
otp                       string|null Generated 6-digit OTP (cleared once verified/locked)
createdAt                 number      Epoch milliseconds when session was created
expiresAt                 number      Epoch milliseconds when OTP expires (+5 mins)
resendAvailableAt         number      Epoch milliseconds when next resend is allowed (+60s)
resendCount               number      Number of resend attempts executed (max 5)
maxResends                number      Static limit (5)
incorrectAttempts         number      Count of incorrect OTP attempts (max 5)
maxIncorrectAttempts      number      Static limit (5)
isVerified                boolean     True once OTP has been successfully verified
isUsed                    boolean     True once new password has been set
verifiedAt                number|null Timestamp when OTP was verified
resetToken                string|null One-time token generated on verification (cleared after use)
resetTokenExpiresAt       number|null Timestamp when resetToken expires (+10 mins)
inFlightUntil             number|null Concurrency lock to prevent duplicate emails
lastRequestId             string|null Idempotency key for network retries
targetDocPath             string|null Firestore path of user document
targetUserType            string|null User role / type
targetOrgId               string|null Associated organisation ID
updatedAt                 timestamp   Firestore server timestamp of last update
