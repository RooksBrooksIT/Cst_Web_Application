1. OVERVIEW & SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------
The eBricks approval system is a unified 5-stage lifecycle workflow that governs 
all operational requisitions across construction sites. Requisitions originate from 
Site Supervisors, undergo Manager technical verification, receive Organization HQ 
financial/administrative authorization, undergo Manager final dispatch clearance, 
and culminate in Supervisor physical arrival confirmation.

Supported Requisition Types & Firestore Collections:
  1. Material Requests   -> /organisation/{orgId}/data/siteMaterialsRequest/{docId}
  2. Tools Requisition   -> /organisation/{orgId}/data/siteToolsRequest/{docId}
  3. Workforce Schedule  -> /organisation/{orgId}/data/siteSupervisorProjectStageSchedule/{docId}
  4. Petty Cash / Payment -> /organisation/{orgId}/data/pettyCashRequests/{docId}
  5. Vehicle Movements   -> /organisation/{orgId}/data/vehicleMovements/{docId}

--------------------------------------------------------------------------------
2. THE 5-STAGE APPROVAL LIFECYCLE & STATUS CODES
--------------------------------------------------------------------------------

[Stage 1: Supervisor Submission]
  - Status Code   : "pending_manager_review"
  - Display Label : "Pending Manager Review"
  - Step Number   : 1
  - Description   : Requisition created by Supervisor. Awaiting Manager initial review.

[Stage 2: Manager Verification & Forwarding]
  - Status Code   : "pending_org_approval"
  - Display Label : "Pending Organization Approval"
  - Step Number   : 2
  - Description   : Verified by Manager. Forwarded to Organization HQ for authorization.
  - Rejection Code: "rejected_by_manager" (Step -1)

[Stage 3: Organization HQ Authorization]
  - Status Code   : "pending_manager_clearance"
  - Display Label : "Pending Manager Clearance"
  - Step Number   : 3
  - Description   : Authorized by Organization HQ. Returned to Manager for final clearance & release.
  - Rejection Code: "rejected_by_org" (Step -1)

[Stage 4: Manager Final Clearance & Fulfillment]
  - Status Code   : "approved" (or "awaiting_confirmation")
  - Display Label : "Approved & Dispatched"
  - Step Number   : 4
  - Description   : Manager issues final clearance. Inventory stock is automatically transferred from Company Warehouse to Site.

[Stage 5: Supervisor Receipt Confirmation]
  - Status Code   : "received"
  - Display Label : "Received / Active"
  - Step Number   : 4 (Completed)
  - Description   : Supervisor physically confirms arrival of items/funds at site.

4. ORGANIZATION WEB APPLICATION IMPLEMENTATION INSTRUCTIONS
--------------------------------------------------------------------------------

A. Organization Pending Approvals Query:
------------------------------------------
To query all requisitions requiring Organization HQ action in the Web App, query:
  Collection: /organisation/{orgId}/data/{collectionName}
  Filter    : where('status', 'in', ['pending_org_approval', 'pending_organization_approval', 'manager_verified'])

B. Organization Approval Action (HQ Authorize):
-------------------------------------------------
When the Organization Admin clicks "Approve / Authorize" in the Web App:

1. Update Firestore Document:
   collection: /organisation/{orgId}/data/{collectionName}
   document  : {docId}
   updates   : {
     "status": "pending_manager_clearance",
     "statusDisplay": "Pending Manager Clearance",
     "currentStep": 3,
     "orgApprovedBy": currentUser.displayName,
     "orgApprovalRemarks": userRemarks,
     "updatedAt": Firebase.ServerTimestamp(),
     "approvalHistory": ArrayUnion({
       "step": "3. Organization Authorization",
       "action": "Approved by Organization",
       "actorRole": "Organization",
       "actorName": currentUser.displayName,
       "actorId": currentUser.uid,
       "remarks": userRemarks,
       "timestamp": Firebase.ServerTimestamp(),
       "dateStr": formatDate(now)
     })
   }

2. Write In-App Notification:
   Write to: /organisation/{orgId}/data/notifications
   payload : {
     "title": "✅ Requisition Authorized by HQ",
     "body": "HQ (" + currentUser.displayName + ") authorized Requisition #" + docId + ". Manager clearance required to release to site.",
     "targetRole": "manager_and_organisation",
     "targetRoles": ["manager", "organisation"],
     "requestType": requestType,
     "requestId": docId,
     "docId": docId,
     "siteId": siteId,
     "status": "pending_manager_clearance",
     "senderRole": "Organization",
     "senderName": currentUser.displayName,
     "createdAt": Firebase.ServerTimestamp()
   }

C. Organization Rejection Action (HQ Decline):
-----------------------------------------------
When the Organization Admin clicks "Reject / Decline" in the Web App:

1. Update Firestore Document:
   collection: /organisation/{orgId}/data/{collectionName}
   document  : {docId}
   updates   : {
     "status": "rejected_by_org",
     "statusDisplay": "Rejected by Organization",
     "currentStep": -1,
     "rejectionReason": rejectionReason,
     "rejectedBy": currentUser.displayName,
     "rejectedRole": "Organization",
     "updatedAt": Firebase.ServerTimestamp(),
     "approvalHistory": ArrayUnion({
       "step": "3. Organization Authorization",
       "action": "Rejected by Organization",
       "actorRole": "Organization",
       "actorName": currentUser.displayName,
       "actorId": currentUser.uid,
       "remarks": rejectionReason,
       "timestamp": Firebase.ServerTimestamp(),
       "dateStr": formatDate(now)
     })
   }

2. Write In-App Notification:
   Write to: /organisation/{orgId}/data/notifications
   payload : {
     "title": "❌ Requisition Declined by HQ",
     "body": "Requisition #" + docId + " was declined by HQ (" + currentUser.displayName + "). Reason: " + rejectionReason,
     "targetRole": "manager_and_organisation",
     "targetRoles": ["manager", "organisation"],
     "requestType": requestType,
     "requestId": docId,
     "docId": docId,
     "siteId": siteId,
     "status": "rejected_by_org",
     "senderRole": "Organization",
     "senderName": currentUser.displayName,
     "createdAt": Firebase.ServerTimestamp()
   }

5. INVENTORY & STOCK AUTOMATION RULES
--------------------------------------------------------------------------------
- Material Requisitions: When Manager grants Stage 4 clearance (`managerFinalClearance`), 
  the system automatically deducts available quantity from `materialsAvailability` / `materialTransfer` 
  at Company Warehouse and credits the count to `siteMaterials/{siteId}/materials/{materialId}`.
- Tool Requisitions: Shifts tools from `toolsAtCompany` to `toolsAtSite` upon Stage 4 clearance.
- Petty Cash / Payments: Updates site spending totals in `totalSiteExpensesPerDay` upon release.
