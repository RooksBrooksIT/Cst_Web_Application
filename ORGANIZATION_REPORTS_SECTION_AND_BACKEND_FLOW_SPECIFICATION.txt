1. ARCHITECTURAL HIERARCHY & NAVIGATION
----------------------------------------------------------------------------------------------------
The Organization Reports system is organized around the Central Insights Dashboard 
(accessed via Bottom Navigation Index 3 or Organization Dashboard quick actions) 
and specialized inventory/workforce sub-modules:

                              INSIGHTS DASHBOARD (BottomNav #3)
                                          │
       ┌──────────────────┬───────────────┼───────────────┬──────────────────┐
       │                  │               │               │                  │
[1. Site Expenses]  [2. Stage Exp.]  [3. Status]    [4. Financial]     [5. Petty Cash]
   - Daily Report      - Stage Summary   - Progress    - Financial Status  - Insights

2. REPORTS MODULES: FRONTEND UI & BACKEND DATA SPECIFICATION

----------------------------------------------------------------------------------------------------
MODULE 1: SITE / PROJECT EXPENSES REPORT HUB (OrganizationInsightsScreen)
----------------------------------------------------------------------------------------------------
Frontend Entry & Options:
  1. Site Selector Dropdown: Shows all active sites with canonical formatting.
  2. Report Type Selector:
     - (A) "Daily Site Expense Report" (Single Date Picker)
     - (B) "Date Range Expense Report" (From Date & To Date Range Picker)
     - (C) "Site Summary Report" (Cumulative Site Lifetime Overview)
  3. Action CTA: "GENERATE REPORT"

A. Sub-Report 1A: Daily Site Expenses Report (DailySiteExpensesReportPage)
   - Frontend Elements:
     * Header: Site Name, Date, Supervisor Name, Project Stage (optional filter).
     * 5 Consolidated Breakdown Cards:
       1. Labour Expenses      : Detailed worker roles, counts, unit rates, subtotal.
       2. Material Expenses    : Material names, quantities, unit prices, subtotal.
       3. Food Expenses        : Daily supervisor food allowance amount.
       4. Transport & Fuel     : Vehicle fuel & transportation expenses.
       5. Manager & Org Bills  : Vouchers, bills, contractor payouts for that date.
     * Grand Total Daily Expense Highlight (Big Banner).
     * Action: "Download PDF" / "Print PDF".
   - Backend Firestore Flow:
     * Composite Key: Document ID = `{siteId}_{ddMMyyyy}` (e.g. `SITE001_18092026`).
     * Collection Queries:
       1. `/organisation/{orgId}/siteSupervisorEntries/{siteId}_{ddMMyyyy}`
       2. `/organisation/{orgId}/managerExpenses/{siteId}_{ddMMyyyy}`
       3. `/organisation/{orgId}/organizationExpenses` (.where('siteId', isEqualTo: siteId))
       4. `/organisation/{orgId}/contractorEntries` (.where('siteId', isEqualTo: siteId).where('date', isEqualTo: yyyy-MM-dd))
       5. `/organisation/{orgId}/totalSiteExpensesPerDay` (.where('siteId', isEqualTo: siteId).where('date', isEqualTo: yyyy-MM-dd))

B. Sub-Report 1B: Date Range Expenses Report (SiteExpensesReportPage)
   - Frontend Elements:
     * Date Range Header: e.g., "01 Sep 2026 to 18 Sep 2026".
     * Day-by-day Chronological Accordion Cards:
       - Date, Day Name, Daily Total.
       - Expandable detail view of labours, materials, petty cash, bills.
     * KPI Summary Grid:
       - Total Labour Cost | Total Material Cost | Total Bills/Vouchers | Grand Total.
     * PDF Generation with tables and categorized columns.
   - Backend Firestore Flow:
     * Loops date iterator from `fromDate` to `toDate`.
     * For each day: resolves canonical site doc key `{siteId}_{ddMMyyyy}`.
     * Queries `siteSupervisorEntries`, `managerExpenses`, `organizationEntries`, `contractorEntries`.
     * Merges in memory, filters by `projectStage` (if specified), and computes running sums.

C. Sub-Report 1C: Site Summary Report (SiteSummaryPage)
   - Frontend Elements:
     * Lifetime Financial Performance: Total Budget vs Total Paid vs Total Spent.
     * Category Distribution: Labour %, Material %, Bills %, Incentives %.
     * Supervisor Activity Log & stage progression.
   - Backend Firestore Flow:
     * Direct query on `/organisation/{orgId}/projects/{siteId}`.
     * Direct query on `/organisation/{orgId}/totalSiteExpensesPerDay/{canonicalSiteDocId}`.

MODULE 2: PROJECT STAGE EXPENSES REPORT HUB (ProjectstageInsightsDashboard)
----------------------------------------------------------------------------------------------------
Frontend Entry & Behavior:
  - Stage Selector: Foundation, Plinth, Superstructure, Brickwork, Plastering, Electrical, 
    Plumbing, Flooring, Painting, Finishing.
  - Sub-Reports:
    1. Project Stage Site Summary (`ProjectStageSiteSummaryReport`):
       * Shows all sites currently in that stage and their stage-specific expenditure.
    2. Project Stage Expenses Detail (`ProjectStageExpensesReportPage`):
       * Deep breakdown of labour, materials, bills tagged specifically with `projectStage`.

Backend Firestore Flow:
  - Queries `siteSupervisorEntries` where `projectStage == selectedStage`.
  - Queries `managerExpenses` and `organizationEntries` where `projectStage == selectedStage`.
  - Aggregates stage burn rate against allocated stage budget.

MODULE 3: SITE / PROJECT STATUS & PROGRESS REPORT (SiteStatusReportScreen)
----------------------------------------------------------------------------------------------------
Frontend Elements:
  - Site Status Matrix: Live, In Progress, Planning, Completed, On Hold.

====================================================================================================
3. COMPREHENSIVE BACKEND DATA FLOW & COMPUTATION PIPELINE
====================================================================================================

----------------------------------------------------------------------------------------------------
A. DYNAMIC SITE CANONICAL RESOLUTION
----------------------------------------------------------------------------------------------------
To handle legacy, prefixed, or slugged site IDs across multiple collections, the backend 
report pipeline utilizes `ExpenseService.resolveCanonicalSiteDocId` and `ExpenseService.resolveSiteKeys`:

  1. Input Site ID: "SITE_001" or "ABC Project" or doc.id.
  2. Resolution Algorithm:
     - Checks `projects` and `Site` collections for matching `siteId`, `siteCode`, `siteName`.
     - Generates canonical composite key: `{canonicalSiteId}_{ddMMyyyy}`.
     - Resolves alternate query keys (up to 10 fallback identifiers) for compound `whereIn` queries.

----------------------------------------------------------------------------------------------------
B. REAL-TIME MULTI-COLLECTION AGGREGATION PIPELINE
----------------------------------------------------------------------------------------------------
When generating any comprehensive report (e.g. Date Range Report or Financial Status), 
the background engine executes the following calculation flow:

```
[Firestore Master Sources]
   ├── siteSupervisorEntries  ──> Labours + Materials + Food + Transport
   ├── managerExpenses        ──> Manager Approved Bills & Vouchers
   ├── organizationEntries    ──> Central Direct Organization Bills
   ├── contractorEntries      ──> Contractor Payouts
   ├── siteSupervisorIncentives ──> Performance Incentives
   └── pettyCashTransactions  ──> Direct Site Petty Cash Outflows
                  │
                  ▼
   [ExpenseService Aggregation & De-duplication]
   (Flags checked: isManagerEntry, isOrgEntry, isPettyCash to prevent double-counting)
                  │
                  ▼
   [totalSiteExpensesPerDay Synced Document]
   (Stored at: /organisation/{orgId}/totalSiteExpensesPerDay/{canonicalId})
                  │
                  ▼
   [Frontend Report State / PDF Generation Engine]
   (Calculates Total Income, Actual Outflows, Cash in Hand, Budget Margin, Variance)
```

----------------------------------------------------------------------------------------------------
C. DATE HANDLING & FORMATTING STANDARDS
----------------------------------------------------------------------------------------------------
- Document Storage Key Format : `ddMMyyyy` (e.g., `18092026`)
- Firestore Query Date Format : `yyyy-MM-dd` (e.g., `2026-09-18`)
- In-memory Timestamp Parsing : Accommodates `Timestamp`, `DateTime`, and ISO-8601 `String`
- UI & PDF Display Format     : `dd MMM yyyy` (e.g., `18 Sep 2026`)

----------------------------------------------------------------------------------------------------
D. PDF REPORT GENERATION & EXPORT ENGINE
----------------------------------------------------------------------------------------------------
All reports feature direct PDF generation and printing via Flutter's `pdf` and `printing` packages:
  - Font Engine: Google Fonts Inter (Regular & Bold) via `PdfGoogleFonts.interRegular()`.
  - Layout Standard: ISO A4 format with 32pt margins.
  - Branded Headers: Dynamic Organization Name, App Branding Colors, Generation Timestamp.
  - Tables & Watermarks: Dynamic zebra-striping, currency formatting (₹), and digital verification footer.
  - Native Sharing: Instant preview, AirPrint/Cloud Print, and Save to PDF/Files.
